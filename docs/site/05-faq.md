# 常见问题

汇总商店接入、安装更新、运行期限制与本地开发的常见排查项。

## 商店源与签名

### 添加商店源时提示无法读取 `store.json`

1. 确认商店地址以 `/` 结尾，例如 `https://store.example.com/`。
2. 检查 `{商店地址}api/v1/store.json` 是否返回 `200 OK` 与有效 JSON。
3. 私有商店（`access: "token"`）需在源配置中填写访问令牌，并确保反向代理放行 `Authorization: Bearer`。
4. 若商店位于本机或内网地址，请确认目标系统的本地地址策略已放行对应地址。

### 提示签名校验失败

- 商店轮换了签名密钥而客户端仍保存旧指纹：在商店源中核对并更新公钥指纹；
- 下载过程被截断或中间缓存未同步：刷新商店缓存后重试；
- 本地联调重新生成了 `dist/dev-signing.key`：删除旧本地源后重新添加。

> **注意**：不要尝试绕过或关闭签名校验；正式商店持续校验失败请联系商店维护者核实。

## 安装、兼容性与更新

### 显示“当前系统不支持”

目标系统会依次核对 `format`、`requires.platform` 与 `capabilities` 标记，任一项超出系统支持范围即拒绝安装：

- 应用使用格式 2（如 Wasm 后端、平台接口 v1、MCP 或技能），而当前目标系统仅支持格式 1；
- 应用使用了新版能力标记（如 `widget.account_selector`、`surface.public`、`backend.token_scopes`、`uses.ai.image` 等）。

可在应用详情页「权限与安全 → 能力标记」查看缺失项，升级目标系统后再安装。

### 提示应用标识冲突

本机已存在同 `slug` 的应用（手动上传或来自其他商店源）。因更新严格绑定原来源商店，需先评估数据后卸载旧来源应用，再从目标商店重新安装。

### 更新数据库迁移失败会丢数据吗？

不会。确认更新前系统不改动旧库；确认后先对 `shared` / `public` 数据库做一致性备份，再在事务中按编号执行新增 SQL 迁移与 `migrate()` 钩子。若历史迁移被篡改或执行报错，系统自动回滚并恢复旧版本继续运行。

## 运行期与接口限制

### 受控代理请求超时或失败

1. 确认安装时已将占位上游地址（如 `https://api.example.com`）修改为真实地址，并正确填写凭据；
2. 确认请求路径和方法命中清单的 `proxies[].paths` 与 `methods`，且响应未超过 `max_response_bytes`；
3. 受控代理在生产环境拒绝回环/保留地址，且**不跟随 HTTP 重定向**（避免把 `http://` 301 跳转地址填作上游）。

### 公开页面访问返回 404

声明 `surfaces.public` 的应用安装后**公开入口默认关闭**。需由管理员在应用管理中开启公开入口；未绑定路径别名时可通过默认路径 `/p/<slug>/` 访问。

### 平台 AI 调用返回 403 或 429

- `403`：目标系统未开启对应能力（如生图开关）、当前账号未获授目标模型权限，或该应用的每日调用限额被设为 `0`；
- `429`：该应用当日 AI 调用额度已用尽，可由管理员调整应用每日限额。

## 开发与本地校验

### `appcheck check` 提示导入未声明宿主能力

Go 后端调用了 `sdk/appkit` 中需清单声明的能力（如 `HTTPFetch`、`NotifySend` 或某存储范围），但 `manifest.json` 缺少对应声明。补全清单或移除未使用调用即可。

### 本地修改 `apps/` 后商店页面没有更新

商店静态站点读取的是 `dist/public/api/v1/`。改动应用目录后需重新运行：

```sh
pnpm data
```

仅修改网站代码（`web/`）或文档（`docs/`）时，开发服务器会自动热更新。
