# 安装与更新

本文说明目标系统如何接入商店源、核验签名与安装更新应用。具体界面名称以目标系统实现为准，核心协议对所有兼容 `api/v1` 数据的系统一致。

> **权限边界**：管理商店源、安装、更新与卸载应用属于管理员操作，且应用安装后需按账号或角色显式授权。

## 1. 添加商店源

1. 以管理员身份打开系统「应用管理 → 应用商店 → 商店源」。
2. 填写以 `/` 结尾的商店地址，例如：

```text
https://store.example.com/
```

3. 系统读取 `{商店地址}api/v1/store.json`，展示商店名称、支持的包格式以及 **Ed25519 公钥指纹**。
4. **人工核对指纹**：将页面展示的指纹与商店官方公布的指纹核对一致后确认保存。
5. 若商店的 `access` 为 `token`，按提示填写访问令牌；令牌在服务端加密保存，仅用于请求该商店源。

系统支持配置多个商店源并调整顺序；停用某个源不会影响已安装的应用，但会停止该源的浏览与更新检查。

## 2. 浏览与安装

1. 在商店列表按关键词、分类或应用类型筛选，点击卡片进入详情页查阅简介、权限摘要、接口清单与版本记录。
2. 系统自动核对应用的包格式、`requires.platform` 与 `capabilities` 能力标记；存在未支持的能力时会阻止安装并列出缺失项。
3. 点击 **安装** 后，系统在服务端下载安装包并依次执行：
   - 核验版本签名对应的公钥在已固定列表中，且 Ed25519 签名有效；
   - 核验下载字节的 SHA-256 与签名记录完全一致；
   - 按与手动上传相同的安全规则重新校验清单、文件扩展名、Wasm 导入表与迁移文件。
4. 在 **安装确认** 中核对权限摘要、代理地址、凭据与安装配置项，并确认默认授予策略后完成安装。

## 3. 授权与入口启用

- **账号与角色授权**：安装者默认获得应用访问权限；其余账号或角色需在权限树中按需勾选应用及声明的应用内子权限（`access.permissions`）。
- **公开入口默认关闭**：声明了 `surfaces.public` 的应用安装后不会自动暴露到公网，需管理员在公开入口设置中手动启用并确认路径别名。
- **桌面卡片**：支持 `desktop_widget` 的应用由每位用户在桌面外观设置中自行决定是否展示。

## 4. 一键更新与回滚

- **同源更新**：系统记录每个应用的来源商店 ID，检查更新只读取 `api/v1/index.json` 并在本地比对版本号，不向商店上报已安装清单；更新只从原来源商店拉取，防止同名应用跨源覆盖。
- **增量权限提醒**：新版本若新增路由、外联主机、代理、公开入口、平台能力或具副作用的 MCP 工具，确认页会重点高亮新增项。
- **迁移备份与回滚**：带数据库迁移的应用确认更新前不改动旧数据；确认后系统先对 `shared` / `public` 数据库做一致性备份再按序执行迁移，任一步失败自动回滚并恢复旧版本继续运行。

## 5. 下架提示与卸载

- 当商店发布针对已安装版本的安全通告或将应用标记为已下架时，系统会在应用管理中醒目提示，不会擅自自动停用或卸载。
- 卸载应用时，系统自动停止其定时任务、释放该应用登记的文件管理引用（`files.reference`），并按系统保留策略处理独立数据。
