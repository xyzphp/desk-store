# 提交与评审

## 提交新应用

1. Fork 本仓库，在 `apps/` 下新建以应用标识命名的目录，结构见[应用目录](../develop/02-app-directory.md)。
2. 本地运行 `appcheck check apps/<slug>`，确保校验通过；建议用 `appcheck pack` 打包后在自己的系统中手动安装测试。
3. 提交 Pull Request，说明应用的用途、需要访问的外部服务以及为什么需要这些权限。
4. CI 会校验安装包与 `store.json`，并在检查结果中列出权限摘要。

## 更新已有应用

- 修改了 `package/` 中的任何文件，都必须提升 `manifest.json` 的 `version`，否则 CI 会拒绝。已发布的版本号不能重复使用，新版本必须高于已发布的版本。
- 在 `CHANGELOG.md` 中添加 `## <版本号>` 小节，它会显示在版本列表中。
- 更新需要应用维护者（`CODEOWNERS` 中登记的人）和商店维护者批准。

## 评审重点

评审者会重点检查：

- `gateway_api` 声明的系统接口范围是否与应用用途相符。应用能以当前用户身份读取这些接口的数据，范围越小越好。
- 代理指向的上游服务是否可信，是否只声明了必要的路径和方法。
- 页面是否引用外部脚本、样式或字体（沙箱环境下通常也无法加载），代码是否可读。请提交未混淆的代码；需要构建的项目把源码放在 `src/`，构建结果放在 `package/`。
- 更新是否悄悄扩大了权限。CI 会列出与上一版相比的权限变化。

不会被接受的应用：闭源或混淆的代码、收集与用途无关的数据、未在说明中披露的外部服务、与已有应用重复且没有明显改进的应用。

## 下架与撤回

- 维护者可以在 `store.json` 中设置 `"withdrawn": true` 下架应用，或在 `yanked` 中列出要撤回的版本。
- 下架的应用仍保留记录，已安装的系统会看到提示。
- 发现安全问题请按仓库的安全说明私下报告，不要公开提交 Issue。
